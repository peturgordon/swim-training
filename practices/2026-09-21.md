## Warmup — 500m

## Main set — CSS test (600m)
*(400m + 200m time trial — the framework's field test for Critical Swim Speed, never yet run this season; see [Training Framework](../guides/training-framework.html#tracking))*
- **400m time trial** — maximal, even-paced effort (not sprint-then-fade). Split every 100m, plus an extra split at 50m and at 350m (right where the stroke counts below happen) if you can catch them without breaking rhythm.
- **Recovery** — ~8–10min easy swimming/rest, enough to bring pulse down (not counted toward session distance). A stricter protocol would use longer rest or a separate day for more accuracy — shortened here to fit a first baseline into today's hour; worth doing more strictly on a future retest if tighter precision matters.
- **200m time trial** — same rules: maximal, even-paced effort, splits every 100m, plus extra splits at 50m and 150m.

## Cooldown — 200m
- Easy free/back, relaxed

**Total: 1300m**

## Metrics to capture
- Both time-trial times (400m, 200m) and their 100m splits.
- Stroke count on the **first 50m and last 50m of each time trial** (four counts total: 400-start, 400-end, 200-start, 200-end) — not every length, to avoid competing for attention with pacing during a maximal effort.
- A split time at those same 50m boundaries (50m and 350m in the 400; 50m and 150m in the 200), so each stroke count has a matching time to pair it with.
- After the session: compute CSS = (400 − 200) ÷ (t400 − t200) in m/s, or CSS pace/100m = (t400 − t200) ÷ 2.
- Also compute SWOLF (stroke count + seconds) for each of the four 50m checkpoints, using the paired split and count above.

## Notes
- Replaces today's usual Technique + Aerobic Base slot — the framework's tracking table treats the CSS test as "one full session," not something layered onto a normal technique day.
- This is the first CSS baseline for this training log; retest every 6–8 weeks per the framework, and use the resulting pace to set real interval targets in future sessions instead of placeholder paces.
- Stroke count at the start/end of each time trial doubles as a technique-under-fatigue data point (the framework's single most evidence-grounded tracking metric) — a genuinely maximal, sustained effort like this is one of the better occasions to capture it, alongside the regular Day B/C sessions.
- SWOLF added deliberately as a first attempt at capturing it, not because it's evidence-backed on its own — per the framework, it's "a coaching heuristic... layer it on top of stroke count, don't treat it as an independent signal." Today's goal for this one is just building the measurement habit (catching a split at the same point as a stroke count); some execution noise (a fumbled split, an off-by-one count) is an acceptable cost for a first pass, not a reason to skip it.
